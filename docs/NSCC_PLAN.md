# NSCC 阶段计划（2026-10-27 起草，尚未开始）

CCDS 单卡阶段（DEVLOG S0–S24）的结论是：在 7B + QLoRA 下，**瓶颈主要在标注与知识，而不在训练技巧**。加数据、加商品文本、调类别比例、软标签、先推理再分类，在不受标注噪声影响的口径下都没有稳定收益。还没有回答的问题是：**模型容量和训练方式是不是另一个瓶颈**。这需要多卡或大显存，放到 NSCC 做。

## 一、要回答的问题

每个实验的判断标准在运行前写进 DEVLOG，沿用 CCDS 阶段的规则：3 个种子；与 E2a 三个种子比较；报告 full / clean / merged 三种口径、加不加先验调整、与偏置无关的排序指标；只有在“加先验调整后”且“种子取值范围不重叠”时才算稳定提升。

| 编号 | 问题 | 做法 | 为什么需要 NSCC |
|---|---|---|---|
| N0 | 两个集群的结果能否直接比较 | 在 NSCC 上按 E2a 设定重训 seed 42 并评测，与 CCDS 的 E2a 对比 | 显卡型号与数值实现不同；后面所有对比都依赖这一步 |
| N1 | 更大的模型是否更好 | Qwen2.5-14B-Instruct，E2a 设定（QLoRA），3 个种子 | 14B QLoRA 在单卡 L40S 上也能跑，但训练和打分时间约翻倍；NSCC 可以几个种子并行 |
| N2 | 4bit 量化是否损失效果 | 7B bf16 LoRA（不量化），其余与 E2a 相同，3 个种子 | 显存需求更高；与 E2a 只差量化方式，能单独回答 P8 留下的问题 |
| N3 | 全参数微调是否更好 | 7B 全参数，ZeRO-3，4 卡；学习率需要重新搜索（LoRA 的 1e-4 不适用） | 单卡放不下 |
| N4（可选） | 更大的模型能否当更好的“审计员” | 用 72B 级模型零样本判断 S17 / S24 的盲评样本，与 Claude 的盲评和（如果有）人工结果对比 | 72B 推理需要多卡 |

- 建议顺序：N0 → N2 → N1 → N3。N2 最便宜，而且决定 N1、N3 用量化还是 bf16 作为对照。
- 如果 N1、N3 在三种口径下都没有稳定提升，就可以比较有把握地说：在这份数据上，限制效果的是标注质量和任务本身的歧义，而不是模型或训练方式。这对面试和项目总结来说同样是有价值的结论。

## 二、迁移前要做的事

### 需要先在 NSCC 上核对（目前都是占位）

- [ ] 项目号、队列名、`select=` 资源写法、单作业时限、每人可同时提交的作业数（决定能否像 CCDS 那样必须串行调度）。
- [ ] GPU 型号与显存（A100 40GB / 80GB 还是 H100），决定 N3 的批大小与 ZeRO 设置。
- [ ] 大容量存储路径与配额（模型、数据、产出都不放家目录），计算节点能否访问外网。
- [ ] Python、CUDA 的 module 名称，PyTorch wheel 的 CUDA 版本与驱动是否匹配。

### 代码需要改的地方

- [ ] `scripts/pbs/train.pbs`：`dataset_dir` 写死为 `$DATA_ROOT/llamafactory`，要改成与 `train.sbatch` 一样从 `DATASET_DIR` 读取，并支持 `TRAIN_OVERRIDES`（种子等）。
- [ ] `scripts/pbs/eval.pbs`：仍是最早的“生成 + 打分”流程，测试集路径也是旧的。要改成与 `label_scores.sbatch` 相同的标签打分（`ecomq.eval.score_labels`），这是先验调整、噪声感知评测和排序指标的输入。
- [ ] PBS 版的调度脚本（相当于 `chain.sh`）：用 `qsub` / `qstat` 实现“提交 → 等待 → 失败重试 → 下一步”。如果 NSCC 允许同时提交较多作业，可以改用 PBS 的作业依赖（`-W depend=afterok:`），不必在登录节点轮询。
- [ ] 多卡训练：`train.pbs` 已设置 `FORCE_TORCHRUN=1` 与 DeepSpeed 参数，但没有在真实环境中跑过，需要先用冒烟数据验证。
- [ ] `scripts/setup_env.sh`：按 CCDS 的 `requirements-lock-ccds.txt` 固定版本（transformers 5.6.0、peft 0.18.1、trl 0.24.0、LLaMA-Factory 0.9.5、torch 2.11），避免两边版本不一致造成差异（参数名、默认值在这些库的版本之间变过，见 P5、P6、P18）。

### 数据与模型

- [ ] 在 NSCC 上重新下载 ESCI 原始数据，用同样的命令和种子重新生成 `e1_relevance`、`esci_test2500`、`esci_tune`，再用 `md5sum` 与 CCDS 上的文件逐个比对。抽样是确定性的，文件应完全相同；比跨集群拷贝更可靠，也顺便验证可复现性。
- [ ] 下载 Qwen2.5-7B-Instruct 与 Qwen2.5-14B-Instruct（登录节点或数据传输节点）。

### 第一步的验收（N0）

- NSCC 上的 E2a seed 42 与 CCDS 上的 E2a seed 42 相比，加先验调整后的宏 F1 差距应在 CCDS 三个种子的范围内（0.541 到 0.554）。
- 如果差距超出这个范围，先排查（库版本、量化实现、批大小、数据文件是否一致），再开始 N1 到 N3。

## 三、算力估算（估算，N0 之后更新）

| 实验 | 规模 | 估算 |
|---|---|---|
| N0 | 7B QLoRA × 1 | 训练与两次打分约 1.5 个 GPU 小时 |
| N2 | 7B bf16 LoRA × 3 | 约 4 个 GPU 小时 |
| N1 | 14B QLoRA × 3 | 约 9 个 GPU 小时 |
| N3 | 7B 全参数 × 3 种子 × 2 到 3 个学习率 | 每次约 4 卡 × 1 小时，合计约 25 到 35 个 GPU 小时 |
